# Windows Security Event Analysis

## Investigation Summary

This document records the Windows Security Event Log analysis performed during Project 2.

The investigation focused on authentication activity, explicit credential use, privilege assignments, account changes, process creation, and a controlled failed-authentication event.

---

## Event ID 4624 — Successful Logon

**Event:** Successful account logon
**Logon Type:** 2 — Interactive
**Account:** Normal Windows user account

### Analysis

Logon Type 2 represents an interactive Windows logon, such as signing into the computer directly.

The observed event was consistent with normal user activity.

**Assessment:** Likely benign.

---

## Event ID 4648 — Explicit Credential Use

**Account:** Normal Windows account
**Target:** `localhost`
**Process:** `svchost.exe`

### Analysis

The event involved the local system and the legitimate Windows `svchost.exe` process.

No malicious behavior was established from this event alone.

**Assessment:** Likely benign based on available evidence.

---

## Event ID 4672 — Special Privileges

**Account:** `SYSTEM`
**Event:** Special privileges assigned to a new logon

### Analysis

The event contained multiple special privileges associated with the Windows `SYSTEM` account.

Highly privileged activity associated with `SYSTEM` can occur during normal Windows operating-system activity.

No evidence from this event indicated malicious activity.

**Assessment:** Likely benign.

---

## Event ID 4625 — Controlled Failed Authentication

A controlled failed-login event was intentionally generated by entering an incorrect Windows password once and then successfully authenticating.

### Observed Evidence

| Field                  | Value                             |
| ---------------------- | --------------------------------- |
| Event ID               | 4625                              |
| Failure Reason         | Unknown user name or bad password |
| Logon Type             | 2 — Interactive                   |
| Process                | `svchost.exe`                     |
| Source Network Address | `127.0.0.1`                       |

### Analysis

Event ID 4625 records a failed Windows logon attempt.

The event showed Logon Type 2, indicating an interactive logon. The source address `127.0.0.1` is the local loopback address, indicating local system activity.

Most importantly, the event was intentionally generated as part of this investigation.

**Assessment:** Benign controlled test event.

No Event ID 4732 events were identified.

Event ID 4732 can indicate that an account was added to a security-enabled local group.

No evidence of this activity was identified in the examined Security log.

**Assessment:** No suspicious local-group membership change identified.

---

## Event ID 4688 — Process Creation

No Event ID 4688 events were available in the examined Security log.

### Analysis

Event ID 4688 represents the creation of a new process.

The absence of Event ID 4688 events does **not** prove that no processes were created. It indicates that process-creation auditing data was not available in the portion of the Security log examined.

**Assessment:** Insufficient process-creation logging data available for analysis.

---

## Overall Assessment

The investigation identified normal Windows authentication and privilege activity.

The only deliberately suspicious-looking event was Event ID 4625, which was intentionally generated as a controlled test.

No evidence was identified of:

* Unauthorized account creation
* Suspicious local-group membership changes
* External failed authentication
* Malicious privilege escalation
* Confirmed unauthorized access

The investigation demonstrates the importance of analyzing security events in context rather than treating individual events as automatically malicious.

## Investigation Conclusion

Based on the available evidence, the Windows Security events reviewed during this investigation were assessed as benign or expected activity.

The controlled Event ID 4625 event successfully demonstrated how a security analyst can investigate a failed authentication alert, examine the surrounding evidence, and determine whether the event represents a genuine security incident.

This project was conducted in a controlled environment for educational and cybersecurity portfolio purposes.
